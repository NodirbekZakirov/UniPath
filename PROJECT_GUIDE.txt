UNIPATH — СПРАВОЧНИК ПО ПАПКАМ, ФАЙЛАМ И КОДУ

Как пользоваться
Откройте нужный файл. Комментарий рядом со строкой объясняет действие и использованные функции. В этом справочнике двигайтесь сверху вниз: папка → файл → назначение → термины. Внутренний код Django, кеш и установленные библиотеки заучивать не нужно.

1. ЧТО ЭТО ЗА ПРОЕКТ
UniPath — сайт предварительного сравнения программ бакалавриата и годовых расходов. Python выполняет серверную логику; Django предоставляет обработчики запросов, формы, ORM, вход и админку; SQLite хранит данные; HTML задаёт структуру, CSS — оформление. Каталог: 7 программ трёх реальных университетов. Проверка источников — 22.10.2026, подробности в SOURCES.md.

Путь запроса: браузер → urls.py → функция views.py → проверка формы → данные/расчёт → HTML-шаблон → ответ браузеру.
Модель описывает хранение; форма проверяет ввод; обработчик связывает действия; шаблон выводит результат.

2. КОРНЕВАЯ ПАПКА unipath (ТА, ГДЕ manage.py)
manage.py: передаёт аргументы терминала Django. import os подключает окружение; import sys — аргументы sys.argv. execute_from_command_line запускает команду. Условие __name__ == "__main__" выполняет блок при прямом запуске, а не при импорте.
requirements.txt: Django==5.2.17; == закрепляет версию зависимости. Остальные необходимые Django пакеты устанавливает pip.
.gitignore: исключает из Git локальное окружение, базу, её резервные копии, .env и кеш.
README.md: описание, запуск, обновление, админка, расчёты и проверки.
SOURCES.md: официальные источники и точное объяснение чисел каталога.
PROJECT_GUIDE.txt: этот справочник.
Вложенные папки: unipath — настройки; universities — логика; templates — HTML; static — оформление.

3. ВНУТРЕННЯЯ ПАПКА unipath — НАСТРОЙКИ ВСЕГО САЙТА
__init__.py: обозначает обычный пакет Python; собственных действий нет.
settings.py: определяет базу, приложения, шаблоны, язык, безопасность и перенаправления.
urls.py: выбирает обработчик по адресу запроса.
wsgi.py: создаёт приложение для совместимого веб-сервера.

3.1. settings.py — ПО ПОРЯДКУ СТРОК
import os: подключает модуль; здесь он читает переменные окружения.
from pathlib import Path: подключает объект работы с путями.
BASE_DIR = Path(__file__).resolve().parent.parent: __file__ — этот файл; Path — объект пути; resolve() — полный путь; parent — папка уровнем выше. Две parent приводят к папке с manage.py. / у объекта Path соединяет части пути.
SECRET_KEY: ключ для механизмов подписания Django. os.environ.get(имя, запасное) берёт значение окружения или локальное учебное значение. Это не пароль администратора.
DEBUG: сравнение полученной строки с "1" даёт True/False; True включает подробные ошибки разработки.
ALLOWED_HOSTS: допустимые имена хоста сервера; split(",") разбивает строку по запятым. Это не список разрешённых пользователей.
INSTALLED_APPS: список подключённых приложений. admin — админка; auth — учётные записи и разрешения; contenttypes — служебные сведения о моделях; sessions — сессии; messages — уведомления; staticfiles — статические файлы; universities — наше приложение.
MIDDLEWARE: промежуточные обработчики запроса/ответа. SecurityMiddleware — настройки безопасности; SessionMiddleware — сессия; CommonMiddleware — общая обработка; CsrfViewMiddleware — CSRF; AuthenticationMiddleware — request.user; MessageMiddleware — уведомления; XFrameOptionsMiddleware — заголовок ограничения встраивания во фреймы.
ROOT_URLCONF: адрес модуля маршрутов, unipath.urls означает файл urls.py в пакете unipath.
TEMPLATES: BACKEND — система шаблонов Django; DIRS — папка templates; APP_DIRS=True — поиск внутри приложений; OPTIONS/context_processors автоматически добавляют request, пользователя/разрешения и сообщения в контекст.
WSGI_APPLICATION: путь unipath.wsgi.application — объект application из wsgi.py.
DATABASES: default — основная база; ENGINE — SQLite; NAME — путь к db.sqlite3.
AUTH_PASSWORD_VALIDATORS: UserAttributeSimilarityValidator — сходство с данными пользователя; MinimumLengthValidator — минимальная длина; CommonPasswordValidator — распространённые пароли; NumericPasswordValidator — пароль только из цифр.
LANGUAGE_CODE="ru": язык встроенных сообщений.
TIME_ZONE="Asia/Tashkent": часовой пояс проекта.
USE_I18N=True: поддержка переводов.
USE_TZ=True: работа с датой и временем с учётом часовых поясов.
STATIC_URL="static/": адресный префикс CSS и другой статики.
STATICFILES_DIRS: папка статики на диске; отличается от её адреса в браузере.
DEFAULT_AUTO_FIELD: тип автоматически создаваемого целого ID записи.
LOGIN_URL="login": маршрут входа для гостя на защищённой странице.
LOGIN_REDIRECT_URL="saved": обычный переход после входа, если нет другого разрешённого next.
LOGOUT_REDIRECT_URL="home": переход после выхода.
Настройки — переменные, а не собственные функции. True/False — логические значения. Стандартные классы внутри строк настроек достаточно знать по назначению.

3.2. urls.py — ПО ПОРЯДКУ
from django.contrib import admin: подключает модуль админки.
from django.contrib.auth import views as auth_views: подключает стандартные обработчики под псевдонимом auth_views. as задаёт другое локальное имя.
from django.urls import path: подключает функцию маршрута.
from universities import views: подключает наши обработчики.
urlpatterns = [...]: список маршрутов; [ открывает список, ] закрывает.

Каждая строка path:
"" → views.home, name="home": подбор на главной странице.
"university/<int:pk>/" → views.university_detail, name="university": карточка программы.
"saved/" → views.saved, name="saved": личное избранное.
"costs/" → views.costs, name="costs": общий калькулятор.
"costs/<int:pk>/" → views.costs, name="university_costs": калькулятор с ценой выбранной программы.
"save/<int:pk>/" → views.save_university, name="save": POST-действие сохранения/удаления.
"login/" → auth_views.LoginView.as_view(), name="login": вход.
"logout/" → auth_views.LogoutView.as_view(), name="logout": выход через POST.
"register/" → views.register, name="register": регистрация.
"admin/" → admin.site.urls: набор готовых адресов админки.

ПОДРОБНО ВАШ ПРИМЕР:
path("logout/", auth_views.LogoutView.as_view(), name="logout")
path — функция создания маршрута.
"logout/" — часть адреса после домена; на локальном сервере это /logout/.
auth_views — псевдоним модуля django.contrib.auth.views.
LogoutView — готовый класс Django, завершающий авторизованную сессию.
as_view() — метод класса, создающий вызываемый обработчик HTTP-запроса для urls.py.
name — именованный аргумент функции path; задаёт имя маршрута.
"logout" после name — внутреннее имя, используемое {% url 'logout' %}; это не пароль и не имя файла.
Запятая разделяет аргументы. Круглые скобки вызывают функцию/метод.
Действие строки: подключить POST-выход к /logout/. После выхода настройка LOGOUT_REDIRECT_URL ведёт на главную.

<int:pk>: int принимает целое число из адреса; pk — имя передаваемого параметра, здесь ID программы. Пример /university/3/ даёт pk=3.
views.home передаётся без (): Django вызовет функцию позже, когда придёт запрос. as_view() вызывается при создании маршрутов, но сам выход пользователя происходит только при соответствующем запросе.

3.3. wsgi.py — ЧЕТЫРЕ СТРОКИ
import os: подключает работу с окружением.
from django.core.wsgi import get_wsgi_application: подключает готовую функцию Django.
os.environ.setdefault("DJANGO_SETTINGS_MODULE", "unipath.settings"): setdefault задаёт значение только при отсутствии ключа; указывает модуль настроек.
application = get_wsgi_application(): вызывает функцию и сохраняет объект приложения для WSGI-сервера.
WSGI — стандарт взаимодействия Python-веб-приложения с сервером. Внутренний код get_wsgi_application учить не нужно.

4. ПАПКА universities — ДАННЫЕ И ЛОГИКА ПРЕДМЕТНОЙ ОБЛАСТИ
__init__.py: обозначает пакет; собственной логики нет.
models.py: две собственные модели и список MAJORS. University — одна программа; SavedUniversity — связь пользователя и программы. В базе есть также стандартные таблицы Django, поэтому всего таблиц больше двух.
forms.py: SearchForm проверяет профиль; CostForm — семь значений расходов; DEFAULT_PROFILE и DEFAULT_COSTS — начальные примеры.
matching.py: calculate_match(profile, university) возвращает оценку и четыре объяснения. IELTS/GPA дают по 30, бюджет/специальность — по 20. Страна ограничивает выборку отдельно. 100 баллов не означает гарантированного поступления.
costs.py: calculate_costs(data) считает обучение + (жильё + повседневные траты) × месяцы + перелёты, затем вычитает стипендию в пределах расходов и сравнивает с общим бюджетом.
views.py: получает запрос, вызывает форму/модель/алгоритм и возвращает страницу или перенаправление.
admin.py: настраивает встроенную админку, её колонки, фильтры, поиск и проверку источников.
tests.py: 20 автоматических тестов. UniPathTests наследует TestCase; setUp создаёт исходные данные, self.client имитирует браузер, assert... проверяет ожидаемый результат. База тестов отдельная.

4.1. models.py — ЧТО ХРАНЯТ ПОЛЯ
MAJORS: список пар «код, подпись»: cs, business, engineering.
University: name — название; country/city — местоположение; major — специальность; ielts/gpa — числовые ориентиры; tuition — годовая сумма USD; scholarship — наличие возможностей финансирования; description — описание и уточнения; source_url — официальный адрес; verified_on — дата ручной проверки; is_demo — признак учебной записи.
__str__(self): возвращает название для текстовой подписи объекта.
SavedUniversity: user — ссылка на пользователя; university — ссылка на программу.
ForeignKey связывает таблицы. CASCADE удаляет зависимые сохранения при удалении их пользователя или программы. Удаление сохранения не удаляет программу.
Meta: дополнительные настройки модели. UniqueConstraint запрещает одинаковую пару (user, university).
choices задаёт варианты для проверки/формы, но само по себе не является SQL CHECK-ограничением набора значений.
blank=True разрешает пустое поле при валидации; null=True разрешает NULL в базе. full_clean() запускает полную проверку; обычный model.save() автоматически её не вызывает.

4.2. forms.py — ЧТО ПРОВЕРЯЕТСЯ
SearchForm: IELTS 0–9, GPA 0–5, целый бюджет 0–1 000 000, специальность из MAJORS, необязательная страна из базы.
__init__: настраивает экземпляр формы; super().__init__ сначала выполняет настройку родителя. Затем order_by/values_list/distinct получают неповторяющиеся страны.
CostForm: tuition — обучение за год; months — 1–12 месяцев; housing/living — месячные суммы; travel/scholarship — годовые; budget — общий годовой бюджет. Денежные значения целые и неотрицательные, с верхними границами из исходного файла.
label — подпись; min_value/max_value — границы; widget — HTML-виджет; attrs — его HTML-атрибуты; step — подсказка шага в браузере, не самостоятельная серверная проверка кратности; required=False — необязательное поле.
is_bound: переданы ли форме данные. is_valid(): запускает проверку. cleaned_data: проверенные и преобразованные значения. errors: ошибки. initial: начальные значения несвязанной формы.

4.3. views.py — КАЖДАЯ СОБСТВЕННАЯ ФУНКЦИЯ
home(request): профиль из сессии → форма → необязательный фильтр страны → расчёт программ → сортировка → Paginator по 6 → home.html.
university_detail(request, pk): программа по ID → оценка по текущему профилю → статус собственного сохранения → university.html или 404.
saved(request): собственные сохранения пользователя → связанные программы → оценки → saved.html. login_required требует входа.
save_university(request, pk): требует входа и POST; action=remove удаляет только свою связь; иначе get_or_create не допускает повторного сохранения. Возвращает redirect и уведомление.
register(request): UserCreationForm проверяет регистрацию; при корректном POST form.save() создаёт пользователя с хешем пароля; затем переход на вход.
costs(request, pk=None): получает суммы из сессии, при наличии pk подставляет обучение, проверяет форму, вызывает calculate_costs, сохраняет корректный ввод в сессии и выводит costs.html.
request — объект HTTP-запроса. GET — параметры адреса; POST — данные тела формы; method — метод запроса; user — текущий пользователь; session — данные сеанса.
Профиль хранится в session["profile"], расходы — session["costs"]. Это разные словари, не отдельный постоянный профиль в модели пользователя.
Paginator делит готовые результаты после расчёта; не сокращает число программ, по которым уже посчитана оценка.

4.4. admin.py — ЧТО ДЕЛАЮТ КЛАССЫ
UniversityAdminForm(ModelForm): форма редактирования модели. Meta.model выбирает University, fields="__all__" включает все поля.
clean(): вызывает super().clean(); если реальная запись не имеет источника/даты, raise ValidationError сообщает об ошибке; return data отдаёт проверенный словарь. Это проверка именно формы админки.
UniversityAdmin(ModelAdmin): form — используемая форма; list_display — колонки; list_filter — фильтры; search_fields — поиск.
@admin.register(University) и admin.site.register(SavedUniversity) подключают модели к панели.
site_header/site_title: заголовок панели и вкладки.

4.5. ВЛОЖЕННЫЕ ПАПКИ universities
migrations/: история схемы. __init__.py обозначает пакет; 0001_initial.py содержит Migration с initial=True, dependencies и operations. swappable_dependency ждёт модель пользователя; CreateModel описывает наши таблицы; fields — колонки; options/constraints — ограничение уникальности. Миграция не является резервной копией данных.
management/: пакет пользовательских команд; __init__.py обозначает пакет.
management/commands/: Django ищет здесь модули команд; __init__.py обозначает пакет.
seed_real.py: PROGRAMS — семь проверенных записей, VERIFIED_ON — фиксированная дата, текстовые константы — общие пояснения. Command(BaseCommand) добавляет команду; add_arguments объявляет --replace-demo; handle выполняет импорт; transaction.atomic делает его неделимым. update_or_create ищет по name/major и обновляет defaults. Повторная загрузка не создаёт дублей, но перезаписывает эти семь встроенных записей.
--replace-demo удаляет только известные старые вымышленные имена с учебным флагом и пустым источником; их сохранения удаляются каскадно. Остальные записи и пользователи сохраняются.
seed_demo.py: импортирует Command из seed_real как совместимый псевдоним старой команды. Он больше не генерирует учебные кампусы.

5. ПАПКА templates — СТРАНИЦЫ
base.html: общая разметка, навигация, сообщения, CSS и подвал.
home.html: форма подбора, список результатов, пагинация и объяснение баллов.
card.html: повторяемый фрагмент программы для главной и избранного.
university.html: описание, требования, оценка, кнопка сохранения и официальный источник.
costs.html: поля расходов, итог, остаток/нехватка, цветная разбивка.
saved.html: личное избранное или сообщение о пустом списке.
registration/login.html: форма входа.
registration/register.html: форма создания учётной записи.
{{ ... }} выводит значение контекста; {% ... %} выполняет команду шаблона; {# ... #} — невидимый в готовом HTML комментарий.
extends наследует base; block заполняет область; include подключает card; for повторяет фрагмент; empty задаёт пустой результат; if выбирает ветку; url получает адрес по имени; static — адрес статики; csrf_token вставляет защитный токен.
date форматирует дату. safe отключает экранирование: в проекте используется для доверенных встроенных правил пароля Django.
В шаблоне методы без обязательных аргументов могут вызываться без (): form.as_p, page.has_next, get_major_display. Это синтаксис шаблонов, не обычного Python.
form: method — GET/POST, action — адрес. input.name — ключ значения. label.for связывает подпись с input.id. a.href — переход; target=_blank — новая вкладка; rel=noopener noreferrer — изоляция вкладки и отсутствие Referer.
class связывает HTML с CSS; id задаёт уникальный идентификатор; aria-атрибуты помогают вспомогательным технологиям.

8. КОРОТКИЕ ОПРЕДЕЛЕНИЯ PYTHON
Функция: именованный участок кода, получающий параметры и возвращающий результат. def объявляет, имя(...) вызывает; dev — не ключевое слово для объявления функции.
Метод: функция, связанная с классом/объектом; self — текущий экземпляр. Класс задаёт структуру и поведение, объект — конкретный экземпляр.
Параметр указан при объявлении; аргумент — значение при вызове. name="logout" — именованный аргумент. *args собирает позиционные, **kwargs — именованные аргументы; **словарь также раскрывает словарь в новый.
return завершает функцию и отдаёт результат. print печатает, а не возвращает результат вычисления.
import подключает модуль; from ... import ... — отдельные имена; точка в from .models означает соседний модуль текущего пакета.
= присваивает; == сравнивает; >= проверяет не меньше; != — не равно; in — принадлежность; is None — именно отсутствие значения; += прибавляет с присваиванием.
if/else выбирают действие; for перебирает элементы; and требует оба условия, or — хотя бы одно, not отрицает. Проверки and/or могут завершиться до вычисления второй части.
Список []: упорядоченные элементы. Словарь {ключ: значение}: именованные данные. set(): уникальные значения. Кортеж (a, b): неизменяемая последовательность. None: отсутствие значения. int/float/str/bool: целое, дробное, строка, логическое.
profile["ielts"]: доступ по ключу словаря. university.ielts: атрибут объекта. Метод вызывается со скобками; свойство вроде is_authenticated читается без них.
[calculate_match(profile, university) for university in universities]: списковое включение — результат для каждой программы.
sum(check["weight"] for check in checks if check["passed"]): генератор передаёт в sum веса только выполненных критериев.
lambda result: (-result["score"], result["university"].name): короткая функция ключа; отрицательный балл даёт убывание, имя разрешает равенство оценок. sort меняет список на месте и возвращает None.
f"...{value}...": подстановка значения в строку; :, в числовом формате разделяет разряды.
Двоеточие начинает блок; отступы показывают его границы; # начинает комментарий, который Python не выполняет.

9. СЛОВАРЬ ФУНКЦИЙ И МЕТОДОВ, ВСТРЕЧАЮЩИХСЯ В PYTHON-ФАЙЛАХ
Здесь короткое определение; конкретное действие объясняется комментарием в исходнике.
BigAutoField: тип автоматически растущего целого ID.

FloatField: поле дробного числа; min/max или validators задают границы.
ForeignKey: ссылка на запись другой таблицы; on_delete задаёт поведение при её удалении.

Path: объект для составления путей к файлам и папкам.
PositiveIntegerField: поле неотрицательного целого числа, включая ноль.
SUCCESS: стиль сообщения об успешном выполнении команды.
SearchForm: класс проверки IELTS, GPA, бюджета, специальности и страны.

TextField: поле длинного текста.
URLField: поле веб-адреса с проверкой формата при валидации.
UniqueConstraint: ограничение уникальности указанной пары полей в базе.
UserCreationForm: готовая форма Django для проверки регистрации и сохранения хеша пароля.
ValidationError: ошибка проверки, показываемая формой пользователю.
__init__: метод начальной настройки экземпляра; self — текущий объект.
add_argument: объявляет параметр команды; action=store_true создаёт логический флаг.
all: возвращает QuerySet всех записей модели; SQL обычно выполняется при обращении к результатам.
as_view: метод класса, создающий вызываемый HTTP-обработчик для маршрута.
assertContains: проверяет наличие текста в успешном HTTP-ответе теста.
assertEqual: проверяет равенство фактического и ожидаемого значений.
assertFalse: проверяет ложность выражения.
assertIsNone: проверяет, что значение именно None.
assertIsNotNone: проверяет, что значение не None.
assertNotContains: проверяет отсутствие текста в успешном HTTP-ответе.

calculate_costs: наша функция: расходы → стипендия → оплата и остаток бюджета.

copy: создаёт отдельную поверхностную копию словаря или параметров запроса.

10. ЧТО НУЖНО УМЕТЬ ОБЪЯСНИТЬ НА КОНСУЛЬТАЦИИ
Обязательно: роль папок, путь запроса, path/name/as_view, модели и формы, четыре критерия, цикл и сортировка, калькулятор, собственное избранное и исходные данные каталога.
Достаточно назначения: __init__.py, WSGI, стандартные middleware и типы полей.
Внутренности не заучивать: Django в .venv, автоматически созданный байткод, реализация SQLite и стандартной админки.
У стандартных функций понимать вход, результат и применение здесь. Не нужно воспроизводить реализацию ORM или LoginView.

Короткие ответы:
Почему два бюджета? В подборе — обучение, в калькуляторе — все расходы.
Почему GPA 3.25? Условная нормализация исходного 2.6/4, не официальный порог по шкале 5; исходная шкала видна в карточке.
Что означает 100? Выполнены четыре числовых сравнения; конкурс и все требования не проверены.
Где реальные ссылки? В source_url, на странице программы; остальные основания — SOURCES.md.
Почему не дублируется избранное? get_or_create и UniqueConstraint пары user/university.
Почему нет чужого избранного? filter(user=request.user) ограничивает чтение и удаление владельцем.
Зачем CSRF? Проверка POST-формы помогает блокировать постороннюю отправку от имени пользователя; не заменяет авторизацию и HTTPS.
Где пароли? Django хранит хеши, не открытый текст.
Где запоминается профиль? В сессии; по умолчанию данные в базе, cookie содержит идентификатор. Отдельной постоянной модели профиля нет.
makemigrations/migrate? Первое создаёт описание изменения схемы, второе применяет миграции; тесты проверяют поведение на отдельной базе.
GitHub запускает сайт? Нет, репозиторий хранит исходники; запуск Django выполняется отдельно.
